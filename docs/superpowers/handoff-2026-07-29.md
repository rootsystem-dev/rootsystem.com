## 6. Traps

Things that cost time today. A fresh session will hit these otherwise.

**Do not delete the Netlify site.** Stopping builds is safe — the published
deploy keeps serving. Deleting the site takes `rootsystem.com` down, because the
apex A record still points there. Only safe after item 1.

**`dig +short` cannot verify delegation.** Delegation NS records are returned in
the AUTHORITY section as a referral, not the ANSWER section. `dig +short` prints
only the answer, so comparing two empty results scores as a match. This produced
a false PASS earlier. `scripts/dns-verify.sh` now parses the authority section;
do not "simplify" it back.

**DNSimple `URL` records do not survive a BIND export.** The type is
proprietary and has no BIND representation, so the export emits them as
comments. A plain import-and-diff drops them with no error and no visible
difference. Four live ones were preserved by delegating `rob.` and `kyle.` to
DNSimple, because those hostnames are two labels deep and Cloudflare Universal
SSL covers only one level — proxying them would break TLS, and Redirect Rules
require proxied traffic. Advanced Certificate Manager (~$120/yr) is the
alternative; delegation costs ~$12/yr.

**Cloudflare API tokens: account-owned (`cfat_`) tokens verify at
`/accounts/{id}/tokens/verify`, not `/user/tokens/verify`.** Using the user
endpoint makes a working token look dead. Also check `not_before` / `expires_on`
in the verify payload — a token can report `status: active` while its validity
window has not opened.

**Yarn's age gate will block fresh packages, by design.** `npmMinimalAgeGate`
defaults to 1440 minutes. When a package is quarantined, do not disable the
setting — that is how three supply-chain protections got turned off in this repo
originally. Use a semver range with an aged-in floor (`^14.1.5` rather than
`^14.1.7`), or `yarn add --no-time-gate` for a one-off, or
`npmPreapprovedPackages` for a named package. `.yarnrc.yml` documents this.

**`wrangler.jsonc` `main` must be `@astrojs/cloudflare/entrypoints/server`,** a
package specifier — not a path into `dist`, which does not exist when the
adapter validates the config. Assets live in `./dist/client`.

**Astro's CSRF origin check returns 403 to any POST without a matching
`Origin` header.** Testing form endpoints with plain `curl` looks like a broken
endpoint. Pass `-H "Origin: <site origin>"`.

**`wrangler dev --local` uses an empty in-memory D1.** Migrations applied to the
remote database are not there, so inserts fail with `no such table`. Use
`--remote`, or deploy and test against `workers.dev`.

**Worker asset propagation is eventually consistent.** A route can 404 on first
deploy and resolve on redeploy reporting "no updated asset files to upload".
That is propagation, not a defect — do not go hunting for a build bug.

**`git push -u` trips the destructive-op guard** (reads `-u` as force). Use
`git push origin <branch>`. Push may also be blocked by the permission
classifier, in which case Rob runs it.

## 8. Feedback round 1 — fixed

From a screenshot of the contact success state:

- **Notice unreadable in dark mode.** `.notice` set `background: var(--gray-50)`
  unconditionally while text colour inherited `--fg`, which is white in dark
  mode. Fixed by adding a `--surface` token defined per theme. **Any new panel,
  callout or card must use `--surface`, never a literal grey** — this is the
  failure mode.
- **Missing spaces around inline links.** Astro collapses the newline between a
  text line and a following `<a>`, so "time-sensitive," ran into the address.
  Five instances across both sites, all fixed with explicit `{' '}`.
  When placing a link on its own line inside a paragraph, add `{' '}` at the end
  of the preceding line and after the link.

## 9. Feedback round 2 — fixed

Reviewed against the workers.dev deployments.

- **Green confirmed correct.** The old Chakra theme set
  `primary: baseTheme.colors.green` (`components/theme/index.jsx:18`, visible at
  `28e5297^`), so `primary` was Chakra's default green scale. The five values in
  `tokens.css` match it exactly. Dark-mode links intentionally use
  `primary-400` rather than the old theme's `primary.500`, which was ~4.0:1 on
  `--gray-900` and failed AA.
- **Header links had no hover colour.** Astro compiles scoped `nav a` to
  `nav[data-astro-cid-…] a[data-astro-cid-…]` (0,1,2), which outranks the global
  `a:hover` (0,1,1) in `base.css`. **A scoped component style that sets `color`
  must also set its own `:hover` / `:focus-visible`** — inheriting the global
  one silently does not work. Same applied to `.wordmark`.
- **Forensics had no link hover state** at all. Added `accent` → `accent-2`,
  matching the existing `.cta` behaviour.
- **Forensics ignored the dark-mode system preference.** It was pinned light by
  `DESIGN_DIRECTION = 'a'`. Direction A now has a dark scheme derived from A's
  own palette — deliberately *not* a swap to Direction B, since B argues
  different positioning and switching on OS setting would split the brand.
  Greens in dark come from the main site's dark theme so both properties agree.
- **One hardcoded `#c53030`** in `scope.astro` became a `--danger` token defined
  in all three token blocks. Same failure mode as the round 1 `--gray-50` bug.
